# Linux.do 阅读助手使用手册与示例提示词

适用版本：0.6.4。更新日期：2026 年 10 月 1 日。

这个插件让 ChatGPT 或 Codex 使用你配置的 Linux.do 账号搜索论坛、读取话题和回复，再整理出带原帖链接的答案。它目前提供 **13 个只读工具**。搜索和读取由插件完成，摘要、比较和判断由对话中的模型完成。

本文面向日常使用。首次安装或更换电脑，请看 [Windows 安装与维护](MANAGE-WINDOWS.md)；部署到服务器，请看 [VPS Docker 部署](VPS-DOCKER.md)。

## 开始使用

已安装并完成授权后，打开 Codex，或在已经连接此插件的 ChatGPT 对话中选用“Linux.do 阅读助手”。提问时明确说“去 Linux.do”“去 L 站”，或直接提供话题链接。

例如：

```text
去 L 站搜索最近关于 Codex 的使用体验。先搜索 1 页，挑选 3 个最相关的话题，
阅读正文和关键回复后总结。每个结论附原帖或楼层链接，说明哪些是个人体验。
```

不必记工具名称，也不必每次手动启动服务器。不确定连接是否正常时，使用下方的“连接检查”提示词。普通 Linux 技术问题不会因为名称里有 Linux 就自动使用这个插件。

## 当前能做什么

| 功能 | 能得到什么 | 对应工具 |
|---|---|---|
| 检查论坛登录 | 当前账号与信任等级，不返回 Cookie | `whoami` |
| 搜索帖子 | 标题、话题链接、搜索摘要、标签等；支持关键词和论坛高级筛选 | `search` |
| 将搜索结果整理成 Markdown | 便于复制的标题、链接、摘要列表 | `format_search` |
| 读取话题和回复 | 正文、作者、发布时间、真实楼号、楼层链接及下一页位置 | `get_topic` |
| 将话题整理成 Markdown | 带出处和逐楼内容的可复制文本 | `format_topic` |
| 查看板块 | 当前接口返回的板块名称、ID、描述及数量信息 | `list_categories` |
| 浏览板块话题 | 指定板块的一页话题及是否还有下一页 | `category_topics` |
| 查看标签 | 标签名称、数量及可用的说明 | `list_tags` |
| 浏览标签话题 | 指定标签的一页话题 | `tag_topics` |
| 浏览最新话题 | 论坛“最新”列表的一页内容 | `latest_topics` |
| 浏览热门话题 | 论坛的日、周、月、季度、年度或全部时间热门榜 | `top_topics` |
| 查看用户资料 | 可见的注册时间、信任等级、最后在线时间及发帖、获赞等统计 | `user_info` |
| 查看用户近期活动 | 最近一批发帖、回复的摘要和可用链接 | `user_actions` |

帖子列表通常还包含分类、帖子数、浏览量和点赞数，具体以接口实际返回为准。字段缺失要标为“未提供”；最低等级未知不等于任何人都能访问。`user_actions` 返回的是活动摘要，需要了解完整内容时再读取对应话题。

### 使用范围和限制

- **只读**：不能发帖、回复、点赞、收藏、编辑、删除或发送私信。
- **遵循当前账号权限**：不能绕过等级、板块或其他访问限制，也不能恢复已删除、不可见的内容。
- **不是全站采集器**：搜索和列表都有分页；一次查到的结果不等于所有相关讨论，也不是代表全站用户的统计样本。
- **正文以文本为主**：没有图片 OCR、附件下载解析或站外网页读取工具。只出现在截图、附件或外链中的信息，不能当作已经读到。
- **没有自动内容监控**：不会自行追踪新帖、定时生成日报或保存跨对话的阅读进度。这些需要另外配置自动化或保存结果。
- **不能保证永远可用**：论坛限流、Cloudflare 防护、账号权限、断网或凭证失效都可能导致失败。请求失败不能解释成“没有相关帖子”。

### 每次能读取多少

| 操作 | 当前限制 | 日常建议 |
|---|---|---|
| 搜索 | 默认 1 页，单次最多连续 5 页；查询字符串最多 500 字符 | 先查 1 页，再决定是否扩大范围 |
| 读取话题 | 默认 20 条可见帖子，单次最多 100 条 | 先读正文和前 20 条，长帖按需续读 |
| 板块、标签、最新、热门列表 | 一次取一页，通常约 30 个话题 | 不要把第一页当作全部结果 |
| 用户活动 | 默认最多 20 条，参数上限 30；实际可能更少 | 仅表示最近一批活动，当前没有历史活动翻页参数 |

搜索每页通常约 50 条，但去重、匹配情况和论坛响应会影响数量。一次工具调用也可能产生多次论坛请求，不能把这些上限理解为论坛允许的请求频率。

实际访问论坛默认使用随机间隔：普通请求 1.0–1.8 秒，搜索之间 2.2–3.2 秒；空闲后的首条请求不额外等待。多个入口共用同一缓存时会共享节奏，收到 429 后按服务端提示冷却。具体配置和选值依据见 [请求间隔与限流](REQUEST-PACING.md)。

## 怎样提问更容易得到有用结果

告诉模型四件事：**要查什么、什么范围、读到什么程度、怎么输出**。先筛选少量候选，再读正文，通常比一次要求读完整个论坛更有效。

通用模板：

```text
请使用 Linux.do 阅读助手，查询【主题】。
范围：【时间、板块或标签；没有限制可留空】。
先搜索 1 页，挑选最多 3 个最相关的话题，阅读正文和关键回复。
请按【要点列表／对比表／操作步骤】输出，并给出原帖或楼层链接。
区分帖子明确给出的事实、作者体验和你的推断。
如果只读了部分回复，说明阅读范围；如果证据不足或调用失败，直接说明。
```

不要让模型只凭搜索摘要下结论。涉及“现在还能不能用”“某个问题是否已经解决”，还应核对回复时间、软件版本和作者后续反馈。

## 16 个可复制的提示词

把中括号中的内容换成自己的问题。下面的提示词都用于当前这次对话，不会创建定时任务。

### 01 连接检查

```text
检查 Linux.do 阅读助手是否可用：先确认当前论坛登录，再搜索 1 页“Codex”，
选一个结果读取前 3 条帖子。分别告诉我登录、搜索、读帖是否成功。
不要读取或展示 Cookie、API key，也不要把请求失败说成没有结果。
```

这里检查的是当前对话使用的入口。如果要同时验证本地 Codex 和云端 Tunnel，需要明确要求分别测试两条路径。

### 02 快速找资料

```text
去 L 站搜索“[关键词]”，先查 1 页。
按相关性挑出最多 8 个话题，列出完整标题、链接和一句话说明。
这一轮只做筛选，尚未读取正文的结果请明确标注。
```

### 03 限定时间范围

```text
去 Linux.do 查最近 7 天关于“[主题]”的讨论。
先说明你采用的具体起止日期，再检索并阅读最多 3 个相关话题。
区分话题最初创建时间和本次引用帖文的发布时间；老话题中的新回复也可以纳入。
总结这段时间出现的新信息，并附对应楼层链接。
```

### 04 只找标题相关的话题

```text
在 Linux.do 用标题搜索查找“[关键词]”，按最新结果浏览，先查 1 页。
给出完整标题和链接，再挑 3 个最相关的读取正文。
如果精确词没有结果，可以尝试一次常见同义词，并说明改用了什么词。
```

### 05 读懂一个话题

```text
请阅读这个 Linux.do 话题：[话题链接]。
先读取前 20 条可见帖子，说明楼主想解决什么问题、提出了什么方法、
回复中有哪些有效补充或反对意见。重要结论附楼层链接。
如果后面还有未读回复，告诉我阅读范围和下一次应从哪里继续。
```

### 06 接着读长帖

```text
继续读刚才的话题，从上次返回的 next_start 开始，不重复已经读过的部分。
这次最多读取 100 条可见帖子，只总结新增信息、反例和对前面结论的修正。
保留真实楼号与链接；还有后续内容时，给出新的 next_start。
```

这条提示词依赖本对话保留的话题和分页信息。换了新对话，应同时提供话题链接和上次的 `next_start`。

### 07 比较两个话题的结论

```text
比较这两个 Linux.do 话题：[链接 A]、[链接 B]。
先分别读取正文和关键回复，再比较结论、适用环境、版本、证据和限制。
把真正的观点分歧与使用条件不同分开，不要为了得出统一答案而抹掉差异。
每项比较附来源；未读完的范围单独说明。
```

### 08 做一轮方案调研

```text
我想解决：[目标与使用条件]。
请先在 Linux.do 选用最多 3 组关键词，各搜索 1 页，合并重复话题。
挑出最多 3 个相关话题读取，比较可选方案的前提、操作成本、优缺点和失败案例。
最后给出基于这些帖文的建议，并说明哪些判断仍缺少证据。
```

论坛调研能提供使用经验，不等于对方案做过独立实测。

### 09 排查具体报错

```text
请去 Linux.do 查这个已脱敏的报错：[报错文字]。
我的环境是：[系统、软件版本、相关配置]。
优先找环境相近、作者有后续反馈或明确验证结果的帖子。
读正文后列出可能原因、建议先检查的项目，以及每一步的来源。
这次只给排查建议，不直接执行帖中的命令。
```

### 10 看最新话题

```text
获取 Linux.do 最新话题的第一页，挑出最多 10 个与“[关注领域]”相关的话题。
按完整标题、分类、发布时间和链接列出，并说明这里只筛选了第一页。
列表信息不足以判断内容时，不要编写帖子结论。
```

### 11 看近一周热门讨论

```text
读取 Linux.do 的 weekly 热门榜第一页，按讨论主题归类。
挑 5 个值得进一步阅读的话题，给出完整标题、分类、帖子数、点赞数和链接。
先说明选择理由，暂时不要把榜单标题当成已经验证的结论。
```

这里使用论坛自己的 `weekly` 榜，不承诺对应某个自然周，也不表示话题一定在这一周创建。

### 12 浏览某个板块

```text
先列出 Linux.do 当前可查询的板块，找到“[板块名称]”对应的真实 ID。
再读取这个板块的话题第一页，挑出与“[主题]”最相关的 5 个。
给出完整标题、链接和选择理由。找不到板块时请说明，不要猜 ID。
```

### 13 浏览某个标签

```text
先确认 Linux.do 是否有“[标签名称]”这个标签，再读取它的话题第一页。
列出最多 10 个话题的完整标题和链接。
如果标签名称不完全一致，给出实际存在的候选名称，不要擅自使用不存在的标签。
```

### 14 了解某位作者的近期发帖

```text
查询 Linux.do 用户 [用户名] 的可见资料和最近最多 20 条发帖、回复活动。
按时间整理主要讨论主题、活动摘要及可用链接。
摘要不是完整正文，需要引用具体观点时再读取对应话题。
字段缺失请标为未提供，不要填成 0，也不要声称已经查看其全部历史。
```

这里填写论坛的 `username`，不是显示昵称。

### 15 整理为可复制的 Markdown

```text
把这个 Linux.do 话题的前 20 条可见帖子整理成 Markdown：[话题链接]。
保留话题标题、出处、作者、真实楼号和代码块，并附楼层链接。
正文整理与另外补充的摘要分开，未读取的回复不要加入。
先在当前对话中输出，不自动发布到其他平台。
```

这条需求可用 `get_topic` 读取后由模型排版。若只需插件直接输出带话题出处的逐楼 Markdown，可用 `format_topic`；需要楼层直链或可靠续读时，优先使用 `get_topic`。搜索结果的 Markdown 列表可用 `format_search`。

### 16 核对一个说法

```text
我看到这个说法：[待核实的说法]。
请在 Linux.do 搜索相关讨论，读取支持和反对它的具体帖子。
分别列出可核对的事实、作者个人体验和未经验证的推测，并给出楼层链接。
最后说明这些论坛材料能支持到什么程度；不要用回复数量代替证据。
```

## 搜索筛选和分页

日常可以用自然语言让模型组织查询。需要更精确时，可以要求使用下面的搜索语法；方括号表示占位内容，不要原样保留。

| 目的 | 查询示例 |
|---|---|
| 按最新顺序搜索 | `Codex order:latest` |
| 限定日期之后 | `Codex after:2026-09-01` |
| 同时限定前后日期 | `Codex after:2026-09-01 before:2026-10-01` |
| 只匹配标题 | `Codex in:title` |
| 指定作者 | `Codex @[用户名]` |
| 指定标签 | `Codex tags:[标签名称]` |
| 指定分类 | `Codex #[分类搜索标识]` |

这些筛选由论坛搜索处理，日期边界和匹配结果以论坛规则为准。分类搜索标识不一定等于显示名称；不确定时，直接使用“先列出板块，再按 ID 浏览”的提示词。

分页有两个容易混淆的地方：

- 搜索页码从 **1** 开始；最新、热门、板块、标签列表页码从 **0** 开始。通常让模型处理即可。
- 读帖时，`start` 是可见帖子流中的位置，`floor` 才是真实楼号。不要把“第 100 楼”直接当作 `start=100`；应按返回的 `next_start` 续读，直到它为 `null`。

## 后台运行和凭证更新

Windows 上，Codex 加载本地插件时会启动 MCP，并按需启动或复用 Tunnel。正常情况保持静默，不必留着终端窗口。

| 使用入口 | 连接方式 | 需要保持什么运行 |
|---|---|---|
| 本机 Codex | 直接调用本机 MCP | Codex 的本地插件连接可用 |
| 当前配置的 ChatGPT | 经 OpenAI Tunnel 调用本机 MCP | 这台电脑开机、联网，Tunnel 正常运行 |
| Linux VPS | Docker 服务，可选接入 Tunnel | VPS 和相应容器运行 |

Tunnel 负责连接，不会把程序搬到云端托管。退出 Codex 后，已启动的 Tunnel 可以继续运行；电脑关机、休眠或断网时，本机云端入口无法使用。VPS 部署则不依赖这台电脑持续开机。

**明确凭证失效时才主动提醒：** Windows 后台确认 Tunnel key 鉴权失败，或正常调用发现 Cookie 失效，会弹出一次更新向导。按提示获取新值、隐藏粘贴，验证成功后保存并尝试恢复。关闭窗口后，同一次失效不会反复提醒；仍可手动打开管理脚本更新。

Cookie 不会在空闲时被持续检查；收到新的轮换值会保存，但不能保证永久有效。网络故障、Cloudflare 验证页、普通 403 和限流不会被当作密钥过期来弹窗。Linux VPS 没有桌面更新窗口。

手动维护时，Windows 双击仓库根目录的 `LinuxDo.cmd`：

| 菜单 | 什么时候用 |
|---|---|
| 3 检查状态 | 区分论坛登录问题与 Tunnel 问题 |
| 4 更新 Cookie | 重新获取独立登录会话的 `_t` |
| 5 配置 ChatGPT 授权 | 更新 Tunnel runtime API key |
| 2 启动已配置的通道 | 手动恢复云端连接 |
| 6 停止通道 | 暂时停止云端访问；后续插件加载可能再次启动它 |

Cookie 和 key 只粘贴进本机向导，不放在聊天、提示词或 Git 中。Cookie 更新步骤是：独立或隐身窗口登录 `https://linux.do/login` → 同一窗口打开 `https://linux.do/session/current.json` 确认有 `current_user` → F12 的 Application／存储 → Cookies → 复制 `_t` 的 Value。

VPS 对应命令是 `bash linuxdo.sh status`、`bash linuxdo.sh cookie` 和 `bash linuxdo.sh tunnel-key`。完整说明见 [Windows 管理](MANAGE-WINDOWS.md) 和 [VPS 部署](VPS-DOCKER.md)。

## 遇到问题时

| 现象 | 应怎样理解和处理 |
|---|---|
| 没有发现 Linux.do 工具 | 检查插件是否启用、当前对话是否加载了它；更新后可重新打开对话 |
| 本地可用，ChatGPT 不可用 | 检查 Tunnel、网络和平台关联；本地成功不代表云端路径也已连通 |
| 明确登录失效或 401 | 按向导更新对应凭证，不把值发到聊天 |
| Cloudflare 拦截或 403 | 可能是防护或权限问题，不能直接断言 Cookie 过期；停止连续重试 |
| 429 | 论坛限流，减少调用并稍后再试 |
| 搜索成功但没有匹配 | 再考虑同义词、缩短关键词或放宽时间范围；别与网络失败混淆 |
| 帖子很长但总结很短 | 要求说明实际读取范围，再用续读提示词补齐 |
| 回复中的命令看起来可疑 | 插件把帖子当作资料，不代表其中的命令已经验证；先解释用途再决定是否操作 |

工具清单和限制依据 [服务器实现](../src/linuxdo_mcp/server.py)；后台与更新流程依据 [Windows 管理脚本](../Manage-LinuxDo.ps1) 和 [凭证提醒实现](../src/linuxdo_mcp/credential_alerts.py)。技术安装步骤见 [安装与连接文档](USAGE.md)。
